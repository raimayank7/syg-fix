git reset: soft, mixed and hard

The three modes move the branch back the same way and differ only in what they do with your work.

The same starting point, three results

We made a repository with two commits. Before each reset we also had an unsaved edit to notes.txt and a new file draft.txt that had been added to the staging area. Then we ran each mode with HEAD~1 (one commit back). This is what happened:

CommandBranch moved backStaged changesYour filesgit status --short afterwards
git reset --soft HEAD~1yeskeptkeptA draft.txt; MM notes.txt
git reset --mixed HEAD~1 (the default)yesunstagedkept M notes.txt; ?? draft.txt
git reset --hard HEAD~1yesdroppedreset to the old commitnothing

How to read the table

  • --soft changes only the branch. Nothing else moves, so everything you had stays, and the file from the commit you undid is still staged. In the status, A (added) and MM (changed in the staging area and again in the folder) tell you this.
  • --mixed also empties the staging area. Your edits remain in the files, but Git no longer has them staged: the status shows M (modified, not staged) and ?? (not tracked).
  • --hard also resets the files. The edit to notes.txt is gone and draft.txt, which was only staged, was deleted. The log shows only the older commit.

Which one to choose

  1. You want to commit again differently: --soft.
  2. You want to pick what goes into the next commit: --mixed.
  3. You want the work gone: --hard, after you have checked git status.

The Git manual says that before reset runs, ORIG_HEAD is set to the tip of the current branch, and that --mixed is the default mode. The reflog page of this site shows how to use that to get back from a hard reset.

Does reset delete commits?

It moves the branch, so the commits are no longer reachable from it. They stay in the repository for a while and can be found with git reflog.

Is reset safe after I pushed?

Moving a shared branch back rewrites history for everyone who has it. Use git revert for shared work.
