What the staging area is

Git has a middle step between editing a file and committing it. Knowing it explains most confusing messages.

Three places

  1. Your working folder is the files you see and edit.
  2. The staging area (also called the index) is a list of the changes that will go into the next commit. git add copies a change into it.
  3. The commits are the saved history. git commit turns the staging area into a new commit.

You can stage part of your work and commit only that part. The rest stays in the folder, not yet saved.

The two letters in git status --short

git status --short prints two columns before each file name. The first is the staging area compared with the last commit. The second is your folder compared with the staging area.

You seeIt means
M (M, then a space)Modified and staged
M (space, then M)Modified, not staged
MMStaged, then changed again after staging
A New file, staged
??Not tracked by Git
UUBoth sides changed it (merge conflict)

The situations on this site show real examples: the page about unstaging a file prints M and ?? and the conflict page prints UU.

The commands

  • git add <file> stages a file.
  • git restore --staged <file> takes it out of the staging area without touching the file.
  • git restore <file> throws away your folder changes for that file.
  • git diff shows folder against staging area; git diff --staged shows staging area against the last commit.
Why does Git not simply commit all my changes?

Because it lets you build clean commits: one commit for one idea.

What does git commit -a do?

It stages changes to files that Git already tracks and commits them in one step. It does not add new files.
