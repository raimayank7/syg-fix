Build a tiny MCP server and see the real messages

This server has two tools. We ran it and recorded every message.

Read on 14 November 2026. This field changes fast: check the sources.

The server

Install the SDK with pip install mcp. In version 2 of the SDK the server class is called MCPServer (version 1 called it FastMCP, and importing the old name fails with a message that points to the migration guide). This is the whole server:

"""A tiny MCP server with two tools (add, shout) written with the official Python SDK. Run by verify.py over stdio. Nothing here talks to the internet."""
from mcp.server.mcpserver import MCPServer

mcp = MCPServer('demo')


@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two whole numbers."""
    return a + b


@mcp.tool()
def shout(text: str) -> str:
    """Return the text in capital letters."""
    return text.upper()


if __name__ == '__main__':
    mcp.run()

The text under each function becomes the tool's description, and the types become its input schema.

The server's answer to initialize lists its capabilities and the protocol version. tools/list returns each tool with a description and a JSON Schema for its input and also for its output. tools/call returns the result as text ("42"), as structured content ({"result": 42}) and isError: false.

What happens with mistakes

We also sent two bad requests. A wrong argument type (the text "two" for a whole number) was not run: the server answered with an error text saying that the argument "Input should be a valid integer". Asking for a tool that does not exist gave isError: true with the text "Unknown tool: nothing". In MCP the tool error is returned inside a normal result, so that the model can read what went wrong and try again.

Through the SDK's own client

The SDK's client connected, listed the tools (add, shout) and called shout with "hello", and the result was HELLO.

Next steps

  1. Add a tool that does something useful and safe.
  2. Read the page on MCP security before you give a server access to files or accounts.
  3. Connect the server to an application that supports MCP: see its own documentation.
Why stdio?

It is the simplest transport: the application starts your program and talks to it through its input and output.

Can I write a server in another language?

The project offers SDKs for several languages. We only ran the Python one.
