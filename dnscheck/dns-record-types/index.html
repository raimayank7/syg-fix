DNS record types explained

A DNS record is one line in a domain's address book. The type says what kind of information it holds.

The common types

TypeWhat it holdsExample use
AAn IPv4 addressexample.com points to a server
AAAAAn IPv6 addressThe same server on IPv6
CNAMEAnother name (an alias)www is an alias of username.github.io
MXA mail server and a priorityWhere email for the domain is delivered
NSThe name servers of the domainWhich servers answer for it
TXTTextSite verification, SPF, DKIM and DMARC records
SOAThe start of authority: zone settingsSerial number and timers
CAAWhich certificate authorities may issue certificatesLimits who can make HTTPS certificates

These types were defined in RFC 1035, the basic DNS specification (CAA and AAAA came later).

Rules that surprise people

  1. A CNAME stands alone. A name that has a CNAME should not have other records, and so a CNAME cannot be used at the root of a domain (example.com), where NS and SOA records must exist. Providers offer ALIAS or ANAME records as a workaround.
  2. MX points to a name, not to an address. And that name needs its own A or AAAA record.
  3. TXT is for anything. Long values are split into pieces of up to 255 characters, which the lookup tool joins for you.
  4. Several records of one type are normal. Several A records give several addresses, and several MX records give backups.

Try it

Use the DNS lookup page: github.com for A, NS and MX, and _dmarc.google.com for a TXT record.

What is the difference between A and CNAME?

An A record gives an address. A CNAME says "ask for this other name instead".

Where do I change records?

At whoever runs the DNS of your domain, which is the company named in the name server records. It is often the registrar, but not always.
