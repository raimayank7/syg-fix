RDAP and WHOIS

RDAP is the newer, structured way to ask a registry about a domain.

WHOIS and RDAP

WHOIS is an old text protocol with no fixed format, so every registry printed its answer in a different shape. RDAP (Registration Data Access Protocol, RFC 7483 for the JSON answers) works over the web, returns JSON and uses the same labels everywhere: events such as registration and expiration, status values, name servers and entities such as the registrar.

Finding the right registry

IANA publishes a bootstrap file that maps each top-level domain to the address of its RDAP service. The domain lookup tool on this site uses a copy of it published on 28 October 2026 (the file says so); it lists services for about 1,200 extensions. A few registries are not in it, and the tool says so.

What is not shown

Registries and registrars generally do not publish the names and contact details of private owners. What you can see is the registrar, dates, name servers and statuses.

Why use it

  • Expiry dates: to renew in time.
  • Name servers: to know where the DNS is managed.
  • Status codes: to see locks and holds (see the page on domain status codes).

Limits

Registries may limit how many lookups you make. If you get an error, wait a minute. A domain with no record can still be reserved.

Is WHOIS gone?

It is still used by many, and RDAP is meant to replace it. We use RDAP because it is structured and works from a browser.

Can I find the owner's name?

Not normally.

Sources

  • RFC 7483: JSON Responses for the Registration Data Access Protocol (rfc-editor.org/rfc/rfc7483)
  • IANA RDAP bootstrap file for DNS (data.iana.org/rdap/dns.json), publication 2026-10-28
