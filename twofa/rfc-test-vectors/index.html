One detail that trips people up

The text of RFC 6238 says the test secret is the ASCII string 12345678901234567890 for all modes. The SHA-256 test values were in fact made with that string repeated to 32 bytes (12345678901234567890123456789012) and the SHA-512 values with it repeated to 64 bytes. This is also what the reference code in the RFC does. We checked both readings: the 20-byte secret alone gives none of the 12 SHA-256 and SHA-512 values, the repeated seeds give all of them.

Use them

  1. Set the time step to 30 seconds and digits to 8.
  2. Compute the code for a given Unix time (time divided by 30, rounded down, is the counter).
  3. Compare with the table. The tester on the home page shows the same codes when you enter the secret and a clock difference.
What is the secret in Base32?

The 20-byte seed is GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ.

Are these for real accounts?

No. They are public test values. Never use a published secret for a real account.
