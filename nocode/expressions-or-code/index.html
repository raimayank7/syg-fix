Expressions, Code node or visual nodes?

Use the smallest tool that does the job: an expression for one value, a node for common jobs, code for the rest.

Read on 14 November 2026. Products change quickly: check the sources.

The documentation's table

n8n gives several ways to work with data, and its page compares them:

ApproachUse when you need toExample from the docsAvailable on
ExpressionsSet a single parameter value using existing dataPull {{ $json.city }}, format dates, simple mathCloud and self-hosted
Code nodeWrite full JavaScript or Python for complex transformationsRestructure data, loop through items, use external librariesCloud and self-hosted
AI Transform nodeGenerate transformation code from natural languageGroup by user and sum totals, categorize by sentimentCloud only
Other data transformation nodesCommon operations through a visual interfaceAggregate items, split arrays, sort data, remove duplicatesCloud and self-hosted

Expressions

An expression is a small piece of JavaScript-like code that you put directly into a node parameter using {{ ... }}. It can use data from previous nodes, workflow metadata or environment variables to set the value dynamically.

A simple rule

  1. One field to fill from existing data: an expression.
  2. A common job such as sorting or removing duplicates: a data node.
  3. Anything that needs real logic, loops over items or libraries: the Code node.

Because every approach works on items (see the page on how data moves), your first step is always to look at what the previous node outputs.

Is the AI Transform node available everywhere?

According to the table, it is Cloud only.

Which is faster to learn?

The visual nodes need the least code. We have not measured speed, and the documentation does not compare it.
