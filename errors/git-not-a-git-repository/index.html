Git: fatal: not a git repository

A plain-words explanation of this Git message: what it means, the usual causes, and the steps that fix it.

The messagefatal: not a git repository (or any of the parent directories): .git

Make the error yourself

Run with git version 2.56.0.windows.4. This is the smallest example we could find that shows it.

Commands

git status

Git prints (the real message)

fatal: not a git repository (or any of the parent directories): .git

Why it happens

Almost every Git command works on a repository, which is a folder that has a hidden .git folder inside. Git looks in the current folder and then in each parent folder for that .git folder. The message says it found none. The usual reasons: you are in the wrong folder (one level above or below the project), you never ran git init or git clone for this project, the hidden .git folder was deleted, or the terminal opened in your home folder instead of the project.

How to fix it

  1. Check where you are: pwd (Mac, Linux, Git Bash) or cd (Windows Command Prompt).
  2. Move into the project folder: cd path/to/project. Then run git status again.
  3. If this is a new project, create the repository with git init (the fixed example uses git init -b main to name the first branch main).
  4. If the project lives online, get it with git clone <address> instead of copying files.
  5. Check that the .git folder exists: ls -a shows hidden entries.

The corrected version

Commands

git init -b main
git status

Git prints (the corrected version)

Initialized empty Git repository in ./.git/
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)

How to avoid it

Open your terminal from the project folder (in most editors there is a "Open in terminal" button), so you are always in the right place.

Questions

Can I recover a deleted .git folder?

Only from a backup or from the online copy. Without the folder, the history is gone. Clone the repository again from the remote if there is one.
