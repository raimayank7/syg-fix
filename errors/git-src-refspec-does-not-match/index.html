Git: error: src refspec main does not match any

A plain-words explanation of this Git message: what it means, the usual causes, and the steps that fix it.

The messageerror: src refspec main does not match any

Make the error yourself

Run with git version 2.56.0.windows.4. This is the smallest example we could find that shows it.

Setup used before these commands (a practice folder with no data)
git init -q -b main work
git init -q --bare -b main remote.git
cd work
git remote add origin ../remote.git
cd work

Commands

git push origin main

Git prints (the real message)

error: src refspec main does not match any
error: failed to push some refs to '../remote.git'

Why it happens

You asked Git to push a branch called main, and no local branch of that name exists. There are two usual reasons. The first is that you have not made a commit yet: a branch is created by the first commit, and until then there is nothing to push (the example). The second is that your branch has another name, for example master on older setups, so main does not exist locally.

How to fix it

  1. Check the state with git status and git branch. If there is no commit, add files and commit (git add . and git commit -m "first commit").
  2. If your branch has another name, push that one, or rename it: git branch -M main.
  3. Then push again with git push -u origin main.

The corrected version

Commands

echo hello > f.txt
git add f.txt
git -c user.name=Asha -c user.email=a@example.com commit -m "first commit"
git push origin main

Git prints (the corrected version)

[main (root-commit) b834024] first commit
 1 file changed, 1 insertion(+)
 create mode 100644 f.txt
To ../remote.git
 * [new branch]      main -> main

How to avoid it

Make a first commit right after git init, and check the branch name with git branch before pushing.

Questions

Why do some repositories use master and others main?

The default name changed over time. A repository keeps the name it was created with, and you can choose a name when you create it.
