Cookies: the Set-Cookie header

A cookie is set by one response header and sent back by the browser on later requests. The attributes decide where it travels and who can read it.

A real response

GET /cookie HTTP/1.1
Host: example.com

HTTP/1.1 200 OK
Date: Sat, 14 Nov 2026 10:00:00 GMT
Content-Type: text/html; charset=utf-8
Set-Cookie: sid=abc123; Path=/; Max-Age=3600; HttpOnly; Secure; SameSite=Lax
Content-Length: 9

<p>hi</p>

The browser stores sid=abc123. On later requests to this site it sends Cookie: sid=abc123.

The attributes

AttributeWhat it does
Max-Age=3600Keep the cookie for 3,600 seconds. Without Max-Age or Expires it is a session cookie, removed when the browser closes
Path=/The cookie is sent for every address on the site
SecureThe browser sends the cookie only over a secure channel (https)
HttpOnlyScripts on the page cannot read it through document.cookie
SameSite=LaxThe cookie is not sent with most requests that start on another site, but is sent when a visitor clicks a link to your site
SameSite=StrictSent only for requests that start on your own site
SameSite=NoneSent in all contexts. Browsers require Secure with it
Domain=example.comAlso share the cookie with subdomains. Leave it out to keep the cookie to the exact host

The definitions of Secure and HttpOnly come from the cookie specification (the IETF draft that updates RFC 6265), which we read on 14 November 2026.

Good defaults for a login cookie

  1. Secure, so it never travels over plain http.
  2. HttpOnly, so a script injected into a page cannot steal it.
  3. SameSite=Lax (or Strict for very sensitive actions).
  4. A reasonable Max-Age, with a way to log out that deletes it.

Paste your response into the header checker to see these checks: it flags cookies without the three attributes. It is advice, not a security audit.

Why a cookie may not be saved

  • The attribute Secure on a page loaded over http.
  • SameSite=None without Secure.
  • A domain attribute that does not match the host.
  • The cookie is too large, or the browser blocks third-party cookies.
How big can a cookie be?

Browsers limit the size of each cookie and the number per site. Large cookies also cause 431 errors. Keep session data on the server and put only an identifier in the cookie.

Is a cookie banner needed?

That is a legal question that depends on your country and on what the cookie is for. This site gives no legal advice.
