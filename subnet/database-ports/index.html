The most important rule

A database should talk only to the application servers that need it. If a database port is open to the whole internet, anyone can try to log in, and several databases have, in the past, been installed with no password at all, which led to many public data leaks. Check your own servers: the lists of open ports tell you.

Safe habits

  1. Bind the database to a private address (or localhost) in its configuration, not to every address.
  2. Block the port in the firewall except from the application servers.
  3. Use strong passwords and separate accounts for each application with the minimum rights.
  4. Turn on encryption for connections that cross a network.
  5. Do not use default accounts and empty passwords. Redis in particular is often set up without a password for convenience; set one.
  6. Back up and test the restore.

For developers on a laptop

Connecting to a remote database from your laptop? Use an SSH tunnel or a VPN rather than opening the database port to the internet.
