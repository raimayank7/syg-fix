Sending and receiving use different ports

Email programs use one set of ports to send mail and another to fetch it.

  • Sending to a mail server from your mail program (submission): 587 is the standard submission port (registered as submission). 465 is registered as submissions in current IANA data, for submission with TLS from the start.
  • Server to server (SMTP): 25. This is how mail servers pass mail to each other. Many providers block outgoing port 25 from ordinary home connections to limit spam.
  • Fetching mail: IMAP keeps mail on the server and lets several devices share it (143 plain, 993 with TLS). POP3 downloads mail (110 plain, 995 with TLS).

Which to choose in your mail settings

JobPortSecurity setting
Send587STARTTLS, or 465 with SSL/TLS
Receive, IMAP993SSL/TLS
Receive, POP3995SSL/TLS

Use the encrypted ports. Plain 110 and 143 send passwords and mail in the clear unless the server upgrades the connection.

Safe habits

  1. Always turn on encryption for sending and receiving.
  2. Use an app password or two-step verification where the provider supports it.
  3. If sending fails, check that your provider allows the port you chose; some networks block 25 and 465.
  4. On a server, close ports that you do not use; an open mail relay on port 25 is quickly abused.
