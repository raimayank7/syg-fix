Remote access ports: SSH 22, Telnet 23, RDP 3389 and VNC 5900

What the IANA registry records for these ports, and how to use them safely.

Why this group matters most

Remote access ports let someone control a computer from far away, which makes them valuable to attackers. Servers that have SSH or Remote Desktop open to the internet are tried by automated password guessers within minutes of going online.

The ports

  • 22, SSH (Secure Shell): an encrypted command-line login and file transfer. The right choice for managing Linux and network devices.
  • 23, Telnet: an old command-line login that sends everything, including passwords, in plain text. Replace it with SSH wherever you can.
  • 3389, Remote Desktop (registered as ms-wbt-server): Microsoft's remote desktop protocol, a full graphical login.
  • 5900, VNC (registered as rfb): a graphical remote control protocol. Many VNC setups are weakly protected unless tunnelled.

Safe habits

  1. Do not expose these ports to the whole internet. Allow only your own address, or put them behind a VPN.
  2. Use keys or strong passwords plus two-step verification. For SSH, use key-based login and turn off password login.
  3. Keep the software updated. Remote access services have had serious security flaws.
  4. Consider a different port only as a small extra: changing the port reduces noise in logs, but it is not security.
  5. Log and watch failed logins. Many failed attempts in a short time mean someone is guessing.

If you must support a home user

Use a tool that makes an outgoing connection and requires the user to accept (so no inbound port is open) instead of opening 3389 on a home router.
