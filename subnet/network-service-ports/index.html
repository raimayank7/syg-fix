Network service ports: DNS 53, DHCP 67 and 68, NTP 123, SNMP 161, LDAP 389

What the IANA registry records for these ports, and how to use them safely.

What each one does

  • 53, DNS turns names into addresses. It uses UDP for most questions and TCP for larger answers and zone transfers.
  • 67 and 68, DHCP gives devices their addresses. A server listens on 67 (registered as bootps) and clients use 68 (bootpc).
  • 123, NTP keeps clocks right. Correct time matters for logs, certificates and logins.
  • 161, SNMP lets management tools read the status of network devices. Older versions use only a shared "community" string as a password.
  • 389, LDAP is a directory service used for logins and address books. Its encrypted version uses a different port (636).

Safe habits

  1. Do not run an open DNS resolver or open NTP or SNMP server on the internet. Attackers use them to reflect and amplify traffic, and SNMP can leak details of the network.
  2. Use SNMP version 3 with authentication and encryption where possible; change default community strings.
  3. Restrict DHCP to your own network. A rogue DHCP server hands out wrong addresses and can redirect traffic.
  4. Use encrypted LDAP (LDAPS or STARTTLS) for anything that carries passwords.
  5. Point your devices at trusted time sources.

Troubleshooting pointers

  • A device with an address starting 169.254 did not get an answer from DHCP.
  • Names that do not resolve but addresses that work point to a DNS problem.
  • Certificates that "are not yet valid" or "expired" on a device with the wrong date point to a clock problem.
